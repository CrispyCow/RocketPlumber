# Circuit and MNA interpretation

## What the deep run exercises

The normal calculator tick processes queued commands, updates docking/manoeuvre state, updates components from the previous MNA/derived state, scans reactivation requests, collects primary elements and fluid declarations, performs a possible speculative reactivation trial, then runs the committed solve. The solve calls `update_map_from_inputs!`, `update_mna!`, and `compute_region_temperatures!`; later gameplay uses thrust and advances time. The diagnostic uses the current core calculation APIs with fresh state, so it can reveal a base circuit problem, including one that appears after several ticks. It does not replay the command queue, speculative scheduler, space-map/manoeuvre work, rendering, or every live state transition. If the crash involves one of those phases, inspect its source or reproduce through the actual calculator path.

`collect_primary_map_inputs!` produces `primaryelements`, `primarynodes`, and fluid declarations. The canonical `update_map_from_inputs!` copies active elements into the filtered vector, repeatedly runs `prune!`, `ground_search!`, and `clear_dangling_dependants!` to a fixed point, then indexes filtered nodes, propagates fluids, splits MNA elements, and builds/factorises A. Pruning removes dead branches; ground search excludes current sources and zero-conductance resistors as voltage references; the dangling pass removes dependants whose controller disappeared. An absent element may have been inactive at generation or removed by one of these passes. Compare the primary and filtered listings before interpreting the matrix. An empty filtered circuit is a legitimate result and does not imply singularity.

## Reading an MNA report

`MNA_State` indexes non-ground `NodeCoord`s and voltage sources. Its element dictionaries separate resistors, current sources, and voltage sources. `CONST_RESISTOR` stamps conductance into G; independent current sources contribute to Z; independent and dependent voltage sources add B/C rows and columns; `C_DEP_CURRENT` changes a controlling voltage source's B column; `V_DEP_VOLTAGE` changes C using its controller's terminal voltages. D currently has no stamps. The diagnostic should use FlowEngine's `MNA_buildA_sparse`/cached sparse A rather than maintaining a second set of stamps. If changing solver source, compare `MNA_indexnodes!`, `MNA_splitelements!`, `MNA_stamp_A_ijv!`, `MNA_updateA!`, `MNA_getZ!`, and `MNA_solve!` with the report. FlowEngine tests cover dependent stamps, graph filtering, cache behaviour, and solve cases.

A rank deficit means A has at least one undetermined variable combination under the analysis tolerance. A near-zero singular value or null-vector entry points to involved node voltages or voltage-source currents. It does not establish which placement or source implementation is wrong. Floating islands, contradictory or redundant voltage constraints, zero conductance, missing controllers, and numeric scaling warrant separate checks. A full-rank A can still fail from invalid values, Z construction, nonlinear/component state, a later tick, or an unexercised live path. Matrix rank is a numerical diagnostic; compare singular values and tolerance before interpreting near-singularity.

## Trace elements to the map

`NodeCoord` has `tile` and `dir`; an internal direction belongs to a component's local circuit, while a shared edge direction may join neighbouring placements. A component produces relative elements through `produce_rel_elements` and placement maps them to absolute coordinates. `ElementID` holds a hash of the source tile or pipe edge and a local index, so the hash alone is not a readable coordinate. The deep report matches that hash against loaded component tiles and pipe edges and prints the possible source placement beside each element. Treat a hash match as a lead if multiple placements collide; use the listed endpoint tiles and current element producer to confirm it. A dependent element's `dependent_id` is its controller's identity, not another node.

Inspect the placed component and neighbours with the crash inspector's focus option when a dump is available, or inspect the map directly with `FlowMap.get_component`/`get_pipe`. Then read that component's current `produce_rel_elements`, `update_flowbehav!`, and reactivation or damage methods. For tanks check seal and charge at the inner tank fragment; pressure-fed tanks have separate liquid/gas state. Valves have current and target conductance. Nozzles and turbo pumps can be inactive or damaged. Correlate these values with the generated active elements and the filter result. A component that appears in the map but produces no surviving element can be behaving as designed.
